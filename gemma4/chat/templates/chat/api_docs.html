Chat API

AI-powered chat with real-time air quality context — powered by Gemma 4

v1.0 Base URL: /api/chat/ Format: JSON Auth: Firebase ID token (Bearer) Swagger UI →

ℹ How it works

Authentication — required on every endpoint
Pass a Firebase ID token in the Authorization: Bearer <id_token> header. Requests without a valid token get 401. A session (and its messages) can only be read, modified or deleted by its owner — anyone else gets 403. On POST /sessions/ the user_uid is taken from the token, not from the request body. If Gemma is unavailable, /send/ returns 502 and nothing is saved, so the request can be safely retried.
AI limits
A single AI reply is capped at 1000 output tokens. Each user has a daily quota of 10 000 output tokens; when it is exhausted /send/ returns 429 with tokens_used_today and daily_limit fields. The counter resets at midnight UTC.
AI Assistant — Airi
Every message is processed by the Gemma 4 model. The assistant automatically injects real-time AQI data for the user's city (from Firestore cache or live API calls to AirVisual + OpenWeatherMap). User profile data (name, health condition, activity level) personalises the system prompt on each request.
Session → Messages hierarchy
A session is a named conversation container stored in chat_sessions/{chat_id}. All messages live in its subcollection chat_sessions/{chat_id}/messages/{message_id} and are ordered by created_at.
Auto-title
When the first message is sent to a session whose title is still "New Chat", the title is automatically set to the first 60 characters of the user message.

⚠ Error Response Format

All errors return the same envelope shape:

{ "status": "error", "error": "Human-readable message" }
400 Bad Request — missing required field or invalid JSON body
404 Not Found — session with the given chat_id does not exist
405 Method Not Allowed — wrong HTTP verb used
500 Internal Server Error — Firestore or AI API failure

POST /api/chat/sessions/<chat_id>/send/ Send a message and receive AI reply ▾

The main endpoint. Sends a user message to Gemma 4 and returns the AI reply. Automatically fetches live AQI data and injects it into the model context.

Processing pipeline (in order):
1. Validate session → 2. Load user profile from Firestore → 3. Fetch AQI data for user's city (cache first, then live API) → 4. Build personalised system prompt → 5. Load full message history → 6. Save user message → 7. Call Gemma 4 with history + AQI context → 8. Save AI reply → 9. Update session updated_at + auto-title if first message

Path Parameters

ParameterTypeDescription
chat_id string The session ID

Request Body (JSON)

FieldTypeRequiredDescription
message string Required The user's message text. Cannot be empty.
Request Example

Notes on aqi_used
aqi_used shows the exact AQI data injected into the Gemma context for this request. If AQI data was unavailable (API down, unknown city), this field will be null and the assistant will answer without real-time data. This field is intended for debugging — you may hide it in production.
